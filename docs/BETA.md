# ベータ版を配る前の手順

AETHER のベータ版（プロトコルの版 3）を配る人のための手順です。利用者向けの説明は [README](../README.md)、
設計は [whitepaper](whitepaper.md) を見てください。

## 1. 配る前に確かめること

### コード側（2026-10-09 時点で済んでいるもの）
- 単体テスト（core・client）・clippy 警告 0。
- core の結合テストと、client の重い結合テスト（ノードを何台も立てるもの）がすべて通る。
  - 3 ホップでの公開・検索・取得、私信の初回接触と往復、落ちたリレーがあるときの私信。
  - 保持者の IP に送るのは保持者のガードだけ（R5）、常駐はどの一覧にも載らない（R8）、担当が入れ替わったときの修復。
- 手元の網での測定（4MiB）: 置く量はファイルの 2.45 倍、取る量は 1.06 倍。

### 画面で確かめること（自動では確かめていない）
GUI は `cd gui && npm install && npm run dev` で起動できます。

1. **参加のしかた**: 設定タブで 3 択（一回限り / 常駐 / 常駐＋中継）が出ること。
   - 「常駐」で接続すると、私信のタブに「受け取るには常駐＋中継が必要」と出ること。送るのはできること。
   - 「常駐＋中継」では広告アドレスの欄が出ること。
2. **匿名性の切り替え**: 「上げるファイルの大きさを隠す」「取ったファイルを網に残すのを手伝う」が既定オンで出て、切り替えると保存され、再起動しても残ること。
3. **ファイル**: スレで「ファイルを添付」→ 名前の入力と注意書き → ファイルを選ぶ → 送信中・送信待ち・送信済み、の順に出ること。
   スレに「📎 名前（大きさ）[保存]」が出て、保存で保存先を選べること。取ったファイルが自動で開かないこと。
4. **友だちコード**: 2 台で友だちコードを交換 → トーク → 再起動して自動で接続されること。
5. **古い設定**: 以前の版の設定ファイルがあるフォルダでも起動できること。

### 実際の回線で確かめること（クローズドなベータで）
- 家庭のルータ（NAT）の内側で、常駐（隠れた保持者）として参加でき、置いたファイルを別の人が取れること。
- IPv6 しか外から届かない回線、IPv4 だけの回線のそれぞれで、接続と取得ができること。
- 1GB 前後のファイルを置いて取るのにかかる時間（実網の速さ。目安は 5Mbps）。
- 気になったことは、ログ（CLI は標準出力、GUI は画面の通知）と一緒に知らせてもらう。

## 2. シードのリレー（最初の接続先）を用意する

**アプリにはシードのアドレスを埋め込んでいません。** 配る人が、公開 IP で常時動くリレーを 1 台以上用意し、そのアドレスを利用者に知らせます。

```bash
cargo build --release -p aether-cli
export AETHER_PASSPHRASE='（長いパスフレーズ）'   # 鍵と預かり物を暗号化
./target/release/aether-cli init
./target/release/aether-cli start --relay --port 9443 --advertise <公開IP>:9443
```

- UDP の 9443（QUIC）を外から受けられるようにする（ファイアウォール・セキュリティグループ）。
- シードを 1 台にすると、その運営者に網の入口が集まります。可能なら別の人・別の場所で 2〜3 台。
- シードのリレーの IP は一覧に載ります（中継を引き受ける人は全員そうです）。預かり物は持ちません（リレーは中身を受け付けない）。
- 常時動かすなら、OS の自動起動（systemd など）に登録し、落ちたら再起動するようにしておく。

## 3. 配るもの

- **CLI**: `cargo build --release -p aether-cli` の `target/release/aether-cli`。
- **GUI**: `cd gui && npm install && npm run build`（Tauri。macOS は署名と公証、Windows は SmartScreen の警告への対処が別途要る）。
- 配るときに一緒に伝えること:
  - シードのアドレス。
  - **ベータ版であること**: 外部の監査は未了で匿名性は保証しない。網は作り直すことがあり、古い版とは話せない。
  - [README の「守れるもの・守れないもの」](../README.md#守れるもの守れないもの)。特に「添付のファイル名は読者全員に見える」「写真の位置情報などは消えない」「私信を受け取るには IP が一覧に載る」。
  - 更新は必ず公式の配布元から（「新しい版が出ています」の案内は誰でも出させられる）。

## 4. 配り方について

ソフトウェアの公開とその際の発言が問われた前例があります（Winny の開発者は起訴され、最終的に無罪となるまで 7 年以上かかりました）。
誰が・どこで・どう説明して配るか、どんな使い方を勧め・勧めないかは、コードとは別に決めてください。
権利を侵害する使い方を勧めないこと、既知の限界を隠さないことは、最低限の前提です。
